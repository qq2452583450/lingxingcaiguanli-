# 考试中心并入零星材系统设计

## 背景

现有 `kaoshi` 是独立的 Flask + SQLite 考试系统，包含练习、正式考试、试卷管理、阅卷、成绩查询等功能。零星材管理系统同样是 Flask + SQLite，但已经有内部用户、角色、项目权限和登录会话。

本次目标是把 `kaoshi` 嫁接为零星材系统中的“考试中心”，并沿用零星材系统已有用户账号和密码。供应商账号不参与考试。

## 目标

- 用户只登录零星材系统一次，即可进入考试中心。
- 考试中心使用零星材内部用户表 `users`，不再维护独立考试账号密码。
- 保留考试系统已有核心功能：随机练习、正式考试、成绩查询、题库管理、当前考试试卷设置、主观题阅卷。
- 管理员选择哪套试卷，员工正式考试就考哪套。
- 平时练习继续支持随机抽题。
- 保持手机端可用，页面风格与零星材系统一致。

## 不做范围

- 不接入供应商账号。
- 不保留 kaoshi 独立登录页、注册页、人员审核页。
- 不同步或复制零星材用户密码到考试专用用户表。
- 不重做零星材现有登录、角色、项目权限体系。

## 权限规则

可参加考试的角色：

- 材料员
- 材料审批负责人
- 基地负责人

可管理考试的角色：

- 系统管理员
- 材料审批负责人

供应商角色和供应商门户账号都不能进入考试中心。

## 架构方案

采用“模块并入”方案：把 `kaoshi` 的核心业务拆成零星材系统中的考试蓝图和服务模块。

建议新增结构：

```text
blueprints/exam.py
services/exam_service.py
services/exam_import_service.py
database/exam_schema.py
templates 或 index.html 中的考试模块区域
static/js/exam.js
static/css 中复用现有样式，必要时补充考试样式
```

零星材系统继续由 `app.py` 注册蓝图。考试模块读取 `session['user']` 判断当前登录用户和角色，不再使用 `kaoshi` 的 `session['user_id']`。

## 数据库设计

考试表迁入零星材数据库 `零星材管理系统.db`，统一使用 `exam_` 前缀，避免和现有业务表冲突。

建议表：

- `exam_papers`：试卷主表，保存标题、时长、总分、是否当前考试试卷。
- `exam_questions`：题目主表，保存题型、题干、答案、解析、分值、排序。
- `exam_question_options`：选择题选项。
- `exam_attempts`：正式考试记录，`user_id` 引用零星材 `users.id`。
- `exam_answers`：正式考试答案。
- `exam_subjective_reviews`：主观题阅卷记录，`reviewer_id` 引用零星材 `users.id`。
- `exam_practice_attempts`：练习记录，`user_id` 引用零星材 `users.id`。
- `exam_settings`：当前考试试卷等配置。

原 kaoshi 的 `users` 表不迁入。历史 kaoshi 成绩如需保留，需要单独做用户映射；本设计默认以并入后的新成绩为准。

## 页面入口

零星材左侧菜单增加“考试中心”。

普通考试用户可见：

- 随机练习
- 正式考试
- 我的成绩

考试管理员额外可见：

- 题库管理
- 当前考试试卷设置
- 阅卷管理
- 成绩查询

页面应复用零星材现有单页应用风格，不再使用 kaoshi 原来的独立登录布局。

## 业务流程

### 进入考试中心

1. 用户通过零星材 `/api/login` 登录。
2. 前端保存当前用户信息。
3. 点击“考试中心”。
4. 后端读取 `session['user']`。
5. 如果角色不在允许范围内，返回权限不足。

### 正式考试

1. 员工进入正式考试页。
2. 后端读取 `exam_settings.current_exam_paper_id`。
3. 只允许开始管理员当前指定的试卷。
4. 创建 `exam_attempts` 记录。
5. 提交后自动批改客观题，主观题进入待阅卷。

### 随机练习

1. 员工点击随机练习。
2. 后端从题库中随机抽题。
3. 练习结果写入 `exam_practice_attempts`。
4. 不影响正式考试成绩。

### 阅卷与成绩

1. 系统管理员或材料审批负责人进入阅卷。
2. 查看待阅卷主观题。
3. 保存主观题最终分。
4. 系统计算最终成绩。
5. 成绩查询支持按人员、角色、项目、试卷、状态筛选。

## 安全与一致性

- 后端必须用 `session['user']` 做权限判断，不能只依赖前端隐藏菜单。
- 写操作沿用零星材现有 CSRF 机制，提交请求带 `X-CSRF-Token`。
- 考试开始、提交、阅卷都要校验用户权限和记录归属。
- 成绩查询中普通员工只能看自己的成绩；考试管理员可查看所有成绩。
- 正式考试只允许当前指定试卷，防止用户手动改 URL 考其他试卷。

## 迁移策略

1. 在零星材数据库中新增 `exam_` 表。
2. 把 kaoshi 的试卷、题目、选项、当前试卷设置导入新表。
3. 不迁入 kaoshi 独立用户。
4. 若需要保留历史考试成绩，再追加一次用户映射迁移；默认不作为第一阶段范围。
5. 部署后先用测试账号验证考试、练习、阅卷、成绩查询，再开放给内部员工。

## 测试计划

单元测试：

- 角色判断：允许角色可进入，供应商和其他角色不可进入。
- 当前考试试卷限制：只能考管理员指定试卷。
- 随机练习：返回随机题并写入练习记录。
- 正式考试：客观题自动计分，主观题进入待阅卷。
- 阅卷：保存最终分并完成考试。
- 成绩查询：普通员工只能看自己，管理员可看全部。

集成测试：

- 使用零星材登录会话访问考试接口。
- 系统管理员设置当前试卷后，员工正式考试加载同一套试卷。
- 材料审批负责人可以阅卷和查看全部成绩。
- 供应商账号访问考试接口返回权限不足。

页面验证：

- 桌面端左侧菜单和考试页面显示正常。
- 手机端考试、练习、成绩页面可操作。
- 中文题干、选项、答案不乱码。

## 部署方案

第一阶段只在零星材系统仓库开发和部署：

1. 新增考试数据库初始化和导入逻辑。
2. 新增考试蓝图和服务。
3. 新增前端考试中心页面。
4. 本地测试通过后提交并推送。
5. 按零星材系统现有部署流程更新服务器。
6. 线上验证登录、菜单、考试、阅卷、成绩查询。

## 风险点

- 两套系统原密码算法不同，不能简单复制账号密码；必须使用零星材现有登录会话。
- kaoshi 的历史成绩使用原 `users.id`，不能直接等同零星材 `users.id`。
- 零星材是单页应用，kaoshi 是服务端模板页面，前端需要按零星材风格重接一遍。
- 考试过程中如果用户刷新或重复提交，需要用后端状态避免重复生成成绩。
- 中文 Word 题库导入和 Windows 控制台编码容易出现乱码，导入验证要看数据库和页面显示结果。

## 验收标准

- 零星材用户登录后能看到“考试中心”。
- 材料员、材料审批负责人、基地负责人能练习、考试、查看自己的成绩。
- 系统管理员和材料审批负责人能管理试卷、设置当前考试试卷、阅卷、查询全部成绩。
- 供应商不能进入考试中心。
- 管理员设置当前考试试卷后，所有员工正式考试都只能进入该试卷。
- 随机练习题目来自题库，并且每次抽题不是固定顺序。
- 手机端页面可正常完成练习、考试和成绩查询。
