# 询比价导入物资编码冲突修复设计

## 问题

询比价 Excel 导入在同一次请求中自动创建多个未匹配物资时，会根据最新一条物资编码临时拼接新编码。生产物资编码采用 `KMLX00001` 这类无连字符格式，旧算法无法解析，并在第二个新物资上重复生成同一编码，触发 `materials.material_code` 唯一约束。

## 方案

导入接口继续保留现有的物资匹配和自动创建流程，只把临时编码算法替换为项目已有的 `generate_material_code`。编码生成时使用草稿所属项目的 `project_code` 和当前用户，保证区域前缀正确，并通过生成器已有的查重循环保证每个新物资编码唯一。

接口在确认至少解析出一条有效明细后提交新物资事务，再关闭数据库连接，确保响应中的 `material_id` 可以被后续草稿提交使用。

## 边界

- 不改变 Excel 模板、物资匹配顺序、报价解析或前端交互。
- 不修改已有物资编码和生产数据库记录。
- 项目不存在时仍允许生成通用 `LX` 前缀编码。

## 验证

新增接口回归测试：草稿项目为 `KMJJYC`，数据库最新编码为 `KMLX00050`，一次导入两个无法匹配的物资。导入必须成功，返回并持久化 `KMLX00051`、`KMLX00052`。
